# PBPF 长期实验执行计划

基线版本：7dd64de。分支：longgoal/apbpf-20260916。

## 当前执行顺序
1. 保留原始结果与运行修复，对齐最新代码，运行完整非网络测试。
2. 重建 RunBugRun rich-cache-v3，按锁定设置运行三个种子 A-PBPF 诊断和全部预测控制、强基线。
3. 获取固定版本 CodeARC，分离公共输入与 evaluator 数据，建立源问题级拆分和不可变候选清单。
4. 补齐真实阶段适配器，先通过小规模执行正对照，再生成足量 hard-bank 候选和执行结果。
5. 执行关联、配对不变性、oracle headroom、主动测试、选择、修复与跨模型复验。失败门保留；若收集下游探索结果，明确 nonconfirmatory。
6. 对差结果先查数据、执行器、数值和实现错误；只在训练/开发集选择修正与方法配置。修复后留存新指纹、新尝试和前后差异。
7. 旧 S0–S4 正式协议需要真实部署与 H200/Slurm 资源；持续记录可推进的实现工作与确切外部缺项，不以本地替代结果冒充正式结果。

## 证据与迭代规则
- 本轮三个种子的默认诊断设置在评估前固定。
- 上一轮已经查看的测试结果不能用于确认性方法选择。
- 每次失败、修复、重跑均记录命令、种子、数据/代码校验、训练和评估指标。
- 不降低阈值，不删除失败种子，不伪造集群或 evaluator 身份。
- 模型升级候选先做开发集验证；有限次无改善后回到机制分析，不能无限刷测试集。
