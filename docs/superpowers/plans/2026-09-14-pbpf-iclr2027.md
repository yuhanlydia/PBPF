# PBPF ICLR 2027 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the diagnostic PBPF runner with a mathematically valid,
candidate-specific neural SMC experiment suite, matched-budget repair
evaluation, and a compile-ready ICLR 2027 paper package.

**Architecture:** The offline core owns immutable candidate/version records,
candidate-keyed belief states, exact/NumPy particle mathematics, evaluator
firewalls, deterministic sharding, statistics, and a fake-backend end-to-end
run. Optional Torch/Transformers modules train a semantic belief model and map
one sampled latent to a whole-repair soft prefix; Slurm stages materialize and
resume immutable artifacts rather than sharing mutable databases.

**Tech Stack:** Python 3.11/3.12, NumPy, PyYAML, PyTorch 2.4+, Transformers
4.48+, PEFT, bitsandbytes, datasets, pyarrow, EvalPlus, pytest, Bash, Slurm,
LaTeX/BibTeX.

**Spec:** `docs/superpowers/specs/2026-09-14-pbpf-iclr2027-design.md`

## Global Constraints

- The five modeled outcomes are exactly `PASS`, `WRONG_OUTPUT`,
  `RUNTIME_EXCEPTION`, `TIMEOUT`, and `COMPILE_ERROR`; infrastructure failure
  is separate.
- Every candidate content hash owns an independent belief; only a newly created
  child inherits from its selected parent.
- Test updates on unchanged code contain a likelihood term only. Transition and
  proposal corrections require a sampled root/child latent.
- The primary repair conditioner samples one particle once and holds it for the
  complete continuation; token-level remix is named as a faulty ablation.
- Generator-visible and evaluator-hidden tests are disjoint by construction and
  process boundary. Final hashes are sealed before hidden tests are mounted.
- Formal seeds are exactly `1701`, `1702`, and `1703`; formal repair uses eight
  genuine initial samples and exactly four repair decodes per matched arm.
- Main models are pinned Qwen2.5-Coder-7B-Instruct, non-thinking Qwen3-8B, and
  DeepSeek-Coder-6.7B-Instruct; CPU CI downloads none of them.
- A failed Stage-B gate stops confirmatory repair by default. Forced downstream
  runs are labeled `nonconfirmatory` and cannot populate main tables.
- No legacy `50 -> 84 / 164` diagnostic value is represented as a PBPF result.
- All new behavior is implemented test-first and every implementation task ends
  with a focused commit and independent review.

- [ ] **Step 1: Write failing probability-model tests**

  verifying the intended import failure.

- [ ] **Step 3: Implement semantic encoders and diagonal-Gaussian heads**

  Use explicit tensors rather than candidate-ID hashes. `NeuralBeliefModel`
  exposes `root`, `transition`, `proposal`, `likelihood`, and `future_predict`.
  Clamp log standard deviation to `[-8,4]` and categorical probabilities only
  through `log_softmax`; never store arbitrary probability callbacks.

- [ ] **Step 4: Implement FIVO plus future-prediction loss and calibration**

  Return every incremental log normalizer from filtering. Compute the mixture
  future NLL after prefixes one, two, and four; the confirmatory metric selects
  prefix four. Fit a single positive temperature on calibration logits using
  NLL and persist its split hash.

- [ ] **Step 5: Write the failing `AA/BB` coherence test**

  Use two equal components that assign all mass to `AA` and `BB`. Assert the
  whole-sequence mixture gives `0.5,0,0,0.5`, while token remix gives
  `0.25,0.25,0.25,0.25`. Assert one sampled component ID is reused for every
  token in a fake generation.

- [ ] **Step 6: Implement soft-prefix primary and KV ablations**

  Map `[batch,d_z]` to `[batch,8,d_model]` with a two-layer MLP and prepend to
  `inputs_embeds` with matching attention labels. Implement K-only, V-only, and
  K+V low-rank projectors behind a common shape-checked interface. KV code must
  be optional and never selected by the primary config.

- [ ] **Step 7: Implement exact-gradient serial mixture training**

  First compute per-component sequence sums without gradients and normalize
  responsibilities. Re-run one component at a time and accumulate
  `-rho_m * sequence_logprob_m`; detach belief weights and latents from actor
  loss. Add a test comparing serial gradients with a fully materialized tiny
  mixture.
